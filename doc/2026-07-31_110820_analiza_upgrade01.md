## 3. ŠTO NEDOSTAJE — POTREBNO IMPLEMENTIRATI

### 3.1 Modularna arhitektura `app/` ❌
**Trenutno stanje:** Sav kod je u jednoj datoteci `mamba_voice.py` (1740 linija) — parsiranje, čišćenje, prevođenje, TTS, progress, CLI, history, file management zajedno.  
**Potrebna akcija:** Kreirati `app/` direktorij sa svim Python skriptama prema tablici u sekciji 21.2 dokumentacije. `main.py` postaje čisti orkestrator.

### 3.2 YAML konfiguracija ❌
**Trenutno stanje:** Konfiguracija je u `config/settings.py` — Python rječnik `SETTINGS`. Prednost multi-line stringa je zanemariva jer YAML podržava `|` literal block jednako dobro. Problem: miješanje koda i podataka.  
**Potrebna akcija:**
- Kreirati `config/settings.yaml` (migracija iz `settings.py`).
- Kreirati per-book `work/output/<Knjiga>/config.yaml` generiran iz predloška profila.
- Implementirati `app/config_loader.py` koji čita YAML via `pyyaml`.

### 3.3 CLI "GUI" s kursorskim tipkama ❌
**Trenutno stanje:** `interaktivni_izbornik()` koristi numerički unos. `prikazi_checkbox_izbor()` se poziva ali nije vidljiva u analiziranom kodu — vjerojatno postoji bez kursorske navigacije.  
**Potrebna akcija:** Implementirati `app/menu.py` s `curses` (Unix) ili `msvcrt`+ANSI escape (Windows) za:
- Kretanje ↑↓ kursorskim tipkama, highlight aktivne stavke.
- Potvrda s Enter ili Razmaknicom.
- `X` na dnu svakog podizbornika za povratak.
- Notifikacijska linija s trenutnim OPCIJAMA u izborniku `[3] Prevođenje`.

### 3.4 OPCIJE izbornik s dropdownom ❌
**Trenutno stanje:** Postoji samo bool `SENTENCE_BY_SENTENCE` — nema trećeg moda (odlomak) ni UI dropdowna.  
**Potrebna akcija:** Implementirati OPCIJE izbornik (sekcija 13.5 dokumentacije):
- `[1]` Header u testnoj datoteci: DA/NE dropdown (default: DA).
- `[2]` Granularnost: Odlomak/Paragraf/Rečenica dropdown (default: Paragraf).
- `[3]` Količina (numerički unos, default: 1).
- Promjena se odmah reflektira u notifikacijskoj liniji izbornika.
- Vrijednosti automatski sprema u `config/settings.yaml`.

### 3.5 TEST vs. PRODUKCIJA — ispravna logika headera ⚠️
**Trenutno stanje:** `ADD_METADATA_HEADER` bool zastava primjenjuje se jednako za TEST i produkciju — nema razlikovanja.  
**Ispravan dizajn (nova specifikacija):**
- **Produkcija → UVIJEK čisti tekst, nikad header** — jer se direktno provlači kroz TTS i postaje MP3 audiobook. Header bi se čitao glasom naratora.
- **TEST → header je opcija** (DA/NE, default DA) — koristan za usporedbu modela, vidljive parametre i brzinu.
- Statistike produkcije → zasebna `_stats.txt` datoteka (opcionalno), nikad u glavnoj datoteci.
- Testna datoteka: `<originalni_naziv>_test_<timestamp>.txt`.
- `last_test.json` proširiti s: `test_granularity`, `test_count`, `include_header`.

### 3.6 Checkpoint — prikaz na vrhu glavnog izbornika ⚠️
**Trenutno stanje:** `progress.json` prati jednu aktivnu knjigu. Pri pokretanju se prikazuje R/N/X dijalog za **jedan** nedovršeni posao — nema prikaza više paralelnih checkpointa u glavnom izborniku.  
**Potrebna akcija:**
- Migrirati na `translation_checkpoints.json` s listom `active_books` (više paralelnih).
- U glavnom izborniku odmah na vrhu prikazati blok svih nedovršenih prijevoda s postotkom.
- Odabir jednog → 1-click nastavak bez dodatnih pitanja.

### 3.7 MP3 imenovanje `001_Ch01_part001.mp3` ❌
**Trenutno stanje:** MP3 naziv se izvodi iz TXT naziva poglavlja (npr. `001_prologue-pre-chapter-text.mp3`). Nema `ChXX` komponente ni globalnog rednog broja koji prati sva poglavlja. Nema ni word-count logike za rezanje segmenata — jedan TXT = jedan MP3.  
**Potrebna akcija:** U `app/tts_engine.py`:
- Globalni brojač `NNN` (raspon svih poglavlja).
- Poglavlje brojač `ChXX` (reset po knjizi).
- Dio brojač `partXXX` (reset po poglavlju).
- **Word-count switch:** tekst se procesira rečenicu po rečenicu; kad zbroj dostigne ≥ 500 riječi — segment se zatvori i spremi, nova rečenica otvara novi `partXXX`. Rez uvijek na granici rečenice, nikad usred.
- Pragovi konfigurabilni u `settings.yaml`: `tts.segment.word_limit_soft: 500`, `tts.segment.word_limit_hard: 600`.

### 3.8 ID3 metapodaci u MP3 ❌
**Trenutno stanje:** Nema metapodataka u MP3 datotekama.  
**Potrebna akcija:** Via `mutagen` library pisati ID3 tagove:
- `TPE1` Artist = Autor, `TALB` Album = Naslov knjige
- `TIT2` Title = `Chapter X — Part Y`, `TRCK` Track = globalni redni broj
- `COMM` Comment = verzija aplikacije

### 3.9 Unificirana `FileManager` klasa ⚠️
**Trenutno stanje:** Dvije odvojene slobodne funkcije `generiraj_sigurnu_putanju()` i `generiraj_sigurnu_mapu()` s identičnom logikom, suffix format `(001)`.  
**Potrebna akcija:**
- Objediniti u klasu `FileManager` u `app/file_manager.py`.
- Metode: `ensure_dir()`, `ensure_file_path()`, `book_output_dir()`, `audiobook_dir()`, `ensure_directories()`.
- Suffix: direktoriji `_001`, datoteke `(001)` — prema specifikaciji.
- `suffix_if_exists: bool` parametar za eksplicitno upravljanje.

### 3.10 Per-book `config.yaml` ❌
**Trenutno stanje:** Nema per-book konfiguracije. Svi parametri su globalni.  
**Potrebna akcija:** Pri prvoj obradi knjige kreirati `work/output/<Knjiga>/config.yaml` iz odabranog profila predloška (`profile_sf_literature.yaml` itd.) s book-specifičnim podacima.

### 3.11 `memorija.json` — GLOSSARY i GRAMMAR_FIXES ⚠️
**Trenutno stanje:** `likovi_memorija.json` — flat rječnik `{ime: opis}`, samo CHARACTER profili.  
**Potrebna akcija:**
- Proširiti strukturu na tri sekcije: `CHARACTERS`, `GLOSSARY`, `GRAMMAR_FIXES`.
- Renaming: `likovi_memorija.json` → `<Knjiga>_memorija.json`.
- Proširiti injekciju u system prompt da uključuje sve tri sekcije.

### 3.12 API provideri — Ollama i `.env` ❌
**Trenutno stanje:** LM Studio, OpenAI, Gemini, Qwen — bez Ollama. API ključevi upisani u `settings.py` kao plain text.  
**Potrebna akcija:**
- Dodati `ollama_local` (`http://127.0.0.1:11434/api`) i `ollama_cloud` providere.
- Dodati `custom` provider (generički adapter za nove servise).
- Migrirati sve API ključeve u `.env` datoteku u root direktoriju.
- Čitanje via `python-dotenv` (`os.getenv`); dodati `python-dotenv` u `requirements.txt`.
- `.env` → `.gitignore`; kreirati `.env.example` s praznim vrijednostima za Git.

## 4. PROBLEMI U POSTOJEĆEM KODU

### 4.1 Jedna datoteka 1740 linija — nema separacije odgovornosti
Parsiranje, čišćenje, prevođenje, TTS, progress, CLI, history, file management — sve zajedno. Teško održavanje i proširivanje.  
**Rizik refactoringa:** Srednji — funkcije su dobro dokumentirane i relativno izolirane.

### 4.2 Globalne varijable — antipattern
```python
_TRENUTNA_PUTANJA_KNJIGE: str = ""
_UCITANI_LIKOVI: dict[str, str] = {}
_PREKID_ZAHTJEVAN: bool = False
_HISTORY_IZLAZNI_DIR_TEKST: str = ""
_HISTORY_IZLAZNI_DIR_MP3: str = ""
```
Globalno stanje je krhko i teško testirati. Trebaju postati instance atributi klasa (`Translator`, `TTSEngine`).

### 4.3 Duplikacija API pozivnog koda
`prevedi_odlomak_lm_studio()` i `prevedi_recenicu_lm_studio()` dijele ~60 linija identičnog payload build + urllib koda. Treba ih objediniti u privatnu metodu `_api_call(messages, config)`.

### 4.4 `segmentiraj_poglavlja_po_odlomcima()` — mrtav kod
```python
def segmentiraj_poglavlja_po_odlomcima(tekst):
    return segmentiraj_poglavlja(tekst)  # samo wrapper, nema dodane logike
```
Ukloniti pri refactoringu.

### 4.5 Direktorij struktura razlikuje od specifikacije
**Postojeće u kodu:**
```
input/
input/processed_text/
output/text/
output/mp3/
cache/
```
**Specifikacija:**
```
work/input/
work/output/<Knjiga>/
work/translated/<Knjiga>/
work/audiobooks/<Knjiga>/
work/state/
work/logs/
```
Cjelokupna direktorij struktura treba migraciju.

### 4.6 Konfiguracija u Python modulu umjesto YAML
`config/settings.py` s Python rječnikom `SETTINGS`. Multi-line stringovi su jedina prednost nad YAML-om, ali YAML `|` literal block to rješava jednako dobro. Mješanje koda i podataka treba eliminirati.  
**Rizik migracije:** Nizak — sve vrijednosti su jasno mapirane.

## 7. ZAKLJUČAK

`mamba_voice.py` v1.0.7 ima solidnu funkcionalnu jezgru koja vrijedi sačuvati i migrirati. Sve slabosti su arhitekturne:

1. **Monolitna datoteka** → refactoring u `app/` module je najvažniji i prvi korak.
2. **Python config umjesto YAML** → straightforward migracija, nizak rizik.
3. **Nema CLI GUI** → novi kod u `app/menu.py`, najveći novi feature.
4. **Header logika** → manja izmjena: produkcija uvijek čista, TEST s opcionalnim headerom.
5. **MP3 imenovanje + ID3** → novi kod, nova biblioteka `mutagen`.
6. **Ollama + `.env`** → novi provideri i sigurna pohrana ključeva.

Kod je dobro dokumentiran (docstrings), error handling je konzistentan, atomic write za checkpoint je već implementiran — što čini migraciju predvidljivom i sigurnom.
